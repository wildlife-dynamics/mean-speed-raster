Troubleshooting

Common issues while configuring, running or changing Mean Speed Raster, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the subject group's observations.

The run fails with no observations, or "No Trajectory data left after applying segment filter"

The subject group had no clean fixes in the time range, or every segment fell outside the Trajectory Segment Filter limits. Widen the time range, check the group has collared subjects reporting in that period, and loosen the filter's limits.

Results

Big gaps between cells, or only a few scattered cells

The cells are smaller than the distance between fixes, so many cells are crossed without a segment starting in them. Raise Step Length (e.g. 3000–5000 m) or switch it to Auto.

A few red cells far from the rest, or a very wide top speed class

GPS spikes produce unrealistically fast segments, which stretch the equal-interval classes. Lower Maximum Segment Speed in the Trajectory Segment Filter to a realistic ceiling for the species (e.g. 9 km/h for elephants).

The same colour means different speeds for different subjects

Expected: classes are equal-interval across each view's own speeds. Read each view's legend; use the All view (empty Group by) to compare subjects on one scale.

The run succeeds and files are written, but no dashboard appears

gather_dashboard must run once, not once per view. In spec.yaml it should take files: ${{ workflow.files_single_view.return }} under partial, with no mapvalues. files_single_view should use map with argnames: [view, files]. See the Technical Guide.

Legend colours are out of order

The Sort Ecograph Values step must sit between Build Ecograph and Apply Classification, and classification must read from sort_ecograph. Colours are handed out in the order classes first appear in the table.

Developing

After recompiling, running fails with "Library not loaded: libblas" or a missing .pixi folder

--clobber deleted the generated folder's environment. Run pixi install in ecoscope-workflows-mean-speed-raster-workflow/.

Hand edits to spec.yaml disappeared

EcoWorkbench rewrites spec.yaml from its design each time it compiles the repo. Bring the edits into the design before compiling from EcoWorkbench.

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-mean-speed-raster-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
